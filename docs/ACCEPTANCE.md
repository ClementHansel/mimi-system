# Mimi Chicken OS — Acceptance Matrix

**Owner:** W6-00 (QA lead) · **Created:** 2026-08-19 · **Gate:** G6 — "zero critical/major open; NFR-01..10 each evidenced"

## What this document is for

Before this file existed, "is it tested?" could only be answered by reading the
suites. That made two failure modes easy: assuming a surface was covered
because a nearby one was, and re-testing by hand something a machine already
checks on every push.

So each row below states a **checkable acceptance criterion** and, next to it,
**what actually evidences it today** — a named test file, `manual`, or `NONE`.
The `NONE` rows are the point of the document. They are not a backlog of nice
extras; they are the places where a regression would reach staging unnoticed.

**Coverage is recorded as it IS, not as it should be.** Where a suite exists
but only covers part of a criterion, the row says so rather than claiming the
whole thing.

### How to read the Evidence column

| Marker        | Meaning                                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `e2e:<file>`  | Real browser against a running instance (`pnpm e2e`). Proves the flow works end to end, including routing and permissions |
| `int:<file>`  | Backend integration test against a live database, with real RLS                                                           |
| `unit:<file>` | Pure logic, no I/O                                                                                                        |
| `manual`      | Verified by a person; will not catch a regression                                                                         |
| `NONE`        | Nothing checks this                                                                                                       |

Run everything except the browser suite with `pnpm test`; the browser suite
with `E2E_BASE_URL=<url> pnpm e2e`.

## Standing gaps, ranked

Ranked so the top entry is the next thing worth doing. Items are removed when
closed rather than left in place with a note — a ranking that still lists closed
work stops being a plan. Verified 2026-08-26.

1. **B-16 — CLOSED (2026-08-26).** Every terminal document type `gl-coverage.service.ts` probes (waste records, returns, stock adjustments, petty cash, surat jalan, sj_drops) now publishes `journal.action` at its own approve/dispatch/receive/verify transition, in the SAME transaction as the state change — verified live-DB green in `*-gl-posting.spec.ts` across waste-return, stock-opname, purchasing and pos, plus `int:accounting/gl-coverage.integration.spec.ts` and the balance property test. This pass additionally found and closed a real, separate gap E7 had flagged: `PosOnlineOrderService` never posted the GoFood/ShopeeFood revenue/fee split at all (`ref_type='online_order'`, JOUT-03's online branch) — fixed the same way, `int:pos/pos-online-order-gl-posting.spec.ts`. Two items remain, both flagged rather than silently resolved: (a) `gudang_stock_revaluation` is deliberately NOT wired — Appendix A-8 calls it "a valuation statement, not an event," served by the stock-value report with a manual FIN entry, so inventing a trigger would contradict the contract; (b) documents approved BEFORE their wiring landed have no journal entry and never will on their own — `gl-coverage.service.ts`'s own report exists to size that historical backfill, and running one is explicitly the owner's decision, not something this pass invented an answer to.
2. **B-14 — no HTTPS.** Needs a real domain for a certificate. Blocks live tracking outright and half of the offline suite (F4, C7, NFR-07). **Owner decision — no engineering left to do until the domain exists.**
3. **Offsite backups.** A restore drill passed, but `OFFSITE_REMOTE_CMD` is unset so every dump shares a disk with the database it protects. Fine against a dropped table, worthless if the host dies (NFR-06). **Owner decision — needs a destination and credentials.**
4. **NFR-01 measured but UNPROVEN.** No longer "never run" — it has been run twice (see the NFR-01 row above). The pool ceiling is understood and the `DB_POOL_MAX=20` default is deliberate; the residual failure rate is CPU-bound on a shared 4-core box. Closing this needs the dedicated hardware in `docs/HARDWARE.md`, not a code change.
5. **Backend test files are not typechecked.** `apps/backend/tsconfig.json` excludes `**/*.test.ts` and `**/*.spec.ts`. Measured 2026-08-26: including them surfaces **209 errors, 16 of which are constructor/call ARITY mismatches** (`TS2554`) — the same class as the real defect found this session, where `pos-sync-projector.integration.test.ts` passed 6 arguments to `PosVoidRefundService`'s 7-parameter constructor, silently shifting `notifications` onto the `EventBus` and leaving `eventBus` undefined. The test still passed while exercising misaligned collaborators. Most of the 209 are strictness noise in test code, but the arity subset hides real bugs. **Sizeable follow-up, not a quick fix.**
6. **Residual, accepted:** an attachment with no `location_id` is readable by any authenticated role (`storage.service.ts` documents this in its own comment; proven live by `idor-scope-sweep.spec.ts`). Menu-product photos land here. Also not covered: supplier column-level locking is enforced above the DB so a DB-level sweep cannot prove it (needs an HTTP-level test), and the offline-credential replay path was verified in pieces rather than through a real sync envelope.
7. **Delivery reads are bounded** — the N+1 fan-out, the missing indexes and `my-jobs`' unbounded result set are all fixed. Nothing outstanding.
